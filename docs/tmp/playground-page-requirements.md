# 遊び場ページ 要件整理

## 現状の確認

### データ構造
- **機能コンポーネント**: TransformAnimation, CountUp, DamageEffect, WebCamera, Spinner, GlobalDialog, Login, StripeDemo
- 各コンポーネントは`_domain`ディレクトリに配置されている

### 現状の問題点
1. **Atomic Designのルール違反**: `_domain`ディレクトリにコンポーネントが配置されている（`_components/_organisms/`に移動が必要）
2. **デザインの統一感**: トップページやキャリアページのv2デザインと統一されていない（色、余白、タイポグラフィなど）
3. **情報の見やすさ**: 各機能の説明やタイトルがなく、何ができるのか分かりにくい
4. **レイアウト**: 機能が単純に縦に並んでいるだけで、整理されていない

## 要件

### 機能要件
1. **ページタイトル**
   - H1: 「遊び場」または「Playground」
   - ページの目的を説明するリード文

2. **機能一覧**
   - 各機能をカード形式で表示
   - 各カードに以下を含める：
     - 機能名（タイトル）
     - 機能の説明
     - 実際の機能コンポーネント（デモ）
   - 機能をカテゴリで分類するかどうか（例: アニメーション、認証、決済など）

3. **ページ構造**
   - H1: ページタイトル
   - リード文: ページの目的
   - 機能一覧: 各機能のカード

### 非機能要件
1. **デザイン統一感**
   - トップページ・キャリアページのv2デザインシステムと統一（色、余白、タイポグラフィ）
   - 既存のデザイントークン（`--muted`, `--accent`, `--section-bg`など）を活用
   - カード形式のレイアウト（トップページのSkill/Achievement/Award、キャリアページのCareerCard/SchoolCardと統一感）

2. **情報の見やすさ**
   - 各機能のタイトルと説明を明確に表示
   - 機能のカテゴリ分け（必要に応じて）
   - 適切な余白と行間

3. **レスポンシブデザイン**
   - モバイル（767px以下）: 縦積みレイアウト
   - タブレット・デスクトップ: グリッドレイアウト（2-3カラム）

4. **アクセシビリティ**
   - 適切な見出し構造（h1-h3）
   - セマンティックHTML（`<section>`, `<article>`など）
   - キーボード操作対応
   - スクリーンリーダー対応（適切なaria-labelなど）

5. **パフォーマンス**
   - Suspenseを使用した遅延読み込み（既存の実装を維持）
   - 不要なアニメーションの削減

### コンポーネント構成（Atomic Design）

#### Organisms（ページ専用）
- `app/play_ground/_components/_organisms/PlaygroundSection/PlaygroundSection.tsx` - 機能一覧セクション全体
- `app/play_ground/_components/_organisms/FeatureCard/FeatureCard.tsx` - 機能カード（1件分）

#### Molecules（汎用、必要に応じて作成）
- 既存の`components/molecules/`を活用（必要に応じて追加）

#### Atoms（汎用、既存を活用）
- 既存の`components/atoms/`を活用

## 確認事項（回答済み）

1. **ページタイトル**: 「遊び場」で決定
2. **機能の説明**: タイトルと説明を追加する
3. **カテゴリ分け**: カテゴリで分類する
4. **レイアウト**: グリッドレイアウトと1カラムの両方のパターンをデザイン時に実装する
5. **デザイン方針**: ゼロベースでデザインを検討する
6. **拡張性**: 今後いろんな機能を追加する想定なので、拡張性を考慮する
