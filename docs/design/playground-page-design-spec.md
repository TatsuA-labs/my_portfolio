# 遊び場ページ デザイン仕様書（ゼロベース）

現状の実装に引きずられず、「最適な遊び場ページ」を目的から定義し直したデザインです。トップページ・キャリアページのv2デザインシステムと統一感を保ちながら、機能の追加が容易で、拡張性の高いレイアウトを提案します。

---

## 1. デザインの目的と原則

### 1.1 目的
- **誰向けか**: 採用担当・クライアント・協業したい開発者
- **何を伝えるか**: 開発した機能のデモ、技術力の証明、実装の幅広さ
- **ゴール**: 各機能が分かりやすく整理され、実際の動作を確認できる。今後機能を追加しても統一感が保たれる

### 1.2 原則（ゼロベースで採用）
| 原則 | 具体的な方針 |
|------|----------------|
| **拡張性** | 新しい機能を追加しても統一感が保たれるよう、カード形式で整理。カテゴリで分類し、見つけやすくする |
| **情報の階層化** | カテゴリ → 機能名 → 説明 → デモの順で階層を明確に |
| **可読性** | カード形式で情報を整理し、適切な余白と行間で読みやすく |
| **統一感** | トップページ・キャリアページのv2デザインシステム（色・余白・タイポグラフィ）を活用 |
| **視覚的な整理** | カテゴリごとにグループ化し、グリッドレイアウトで整理 |
| **レスポンシブ** | モバイルファースト。グリッドレイアウト（デスクトップ: 3カラム、タブレット: 2カラム、モバイル: 1カラム）と1カラムレイアウトの両方を実装 |
| **アクセシビリティ** | コントラスト比 WCAG AA、適切な見出し構造、セマンティックHTML・ARIA |

## 2. デザインシステム（トップページ・キャリアページv2と統一）

### 2.1 カラー（既存トークンを活用）
| 役割 | ライト | ダーク | 用途 |
|------|--------|--------|------|
| 背景 | #ffffff | #0a0a0a | カードの背景（`--background`） |
| 文字 | #171717 | #ededed | 本文・見出し（`--foreground`） |
| 補足 | #6b7280 | #9ca3af | 作成日・補足情報（`--muted`） |
| アクセント | #2563eb | #60a5fa | リンク・強調色（`--accent`） |
| セクション背景 | #f8fafc | #111827 | セクション交互の差し色（`--section-bg`） |

### 2.2 タイポグラフィスケール（トップページ・キャリアページと統一）
| 役割 | サイズ | 行間 | 太さ | 用途 |
|------|--------|------|------|------|
| H1 | 1.75rem〜2rem（28〜32px） | 1.25 | 700 | ページタイトル「遊び場」 |
| H2 | 1.5rem（24px） | 1.3 | 700 | カテゴリ名 |
| H3 | 1.25rem（20px） | 1.4 | 600 | 機能名 |
| 本文 | 1rem（16px） | 1.7 | 400 | 説明文 |
| 作成日・補足 | 0.875rem（14px） | 1.5 | 400 | 作成日・ラベル |

### 2.3 スペーシングスケール（8pxベース、トップページ・キャリアページと統一）
| トークン | 値 | 用途例 |
|----------|-----|--------|
| xs | 8px | アイコンとラベルの間 |
| sm | 16px | カード内パディング、リスト項目間 |
| md | 24px | カード内ブロック間 |
| lg | 32px | 見出しとコンテンツの間 |
| xl | 48px | カード間のgap（モバイル） |
| 2xl | 64px | セクション間、カード間のgap（デスクトップ） |

### 2.4 ブレークポイント（トップページ・キャリアページと統一）
| 名前 | 幅 | 方針 |
|------|-----|------|
| モバイル | 〜767px | 1カラム、カード全幅 |
| タブレット | 768px〜1023px | 2カラム、max-width制限 |
| デスクトップ | 1024px〜 | max-width 1100px、3カラム、中央寄せ |

## 3. ページ構造とセクション順

1. **ヘッダー** — 他ページへの動線（既存のHeaderコンポーネントを活用）
2. **ページタイトル** — H1「遊び場」+ リード文
3. **カテゴリ一覧（目次）** — カテゴリへの直接アクセスリンク
4. **機能一覧セクション** — カテゴリ別にグループ化
   - カテゴリ1（例: アニメーション）
     - H2: 「アニメーション」
     - FeatureCard[]（グリッド or 1カラム）
   - カテゴリ2（例: UIコンポーネント）
     - H2: 「UIコンポーネント」
     - FeatureCard[]（グリッド or 1カラム）
   - ...（他のカテゴリ）
4. **フッター** — 他ページへの動線（既存のFooterコンポーネントを活用）

## 4. コンポーネント仕様（ゼロベース）

### 4.1 ページタイトル（H1）

| 要素 | 仕様 | 意図 |
|------|------|------|
| レイアウト | 全幅、padding 上下 2xl（デスクトップ）または xl（モバイル）、中央寄せ | ページの入り口を明確に |
| H1 | 「遊び場」、H1のフォントサイズ・行間、中央寄せ | ページの目的を明確に |
| リード文 | H1の下、1〜2行、本文サイズ、`--muted`色、max-width 65ch、中央寄せ | ページの目的を説明 |
| 区切り線 | リード文の下、hr要素、`--muted`色、opacity 0.5、幅100%、高さ1px | 視覚的な区切り |

### 4.2 カテゴリ一覧（目次 - Organism）

| 要素 | 仕様 | 意図 |
|------|------|------|
| コンテナ | 全幅、padding 上下 xl（デスクトップ）または lg（モバイル）、背景`--section-bg` | 目次を明確に表示 |
| H2 | 「カテゴリ一覧」、H2のフォントサイズ・行間、左寄せ、margin-bottom md | 目次の見出し |
| カテゴリリンク | カテゴリごとにリンク、横並び（デスクトップ）または縦積み（モバイル）、gap sm、`--accent`色、hoverで下線 | カテゴリへの直接アクセス |
| スクロール | クリックで該当カテゴリまでスムーススクロール | アクセスしやすくする |

### 4.3 機能一覧セクション（PlaygroundSection - Organism）

| 要素 | 仕様 | 意図 |
|------|------|------|
| コンテナ | 全幅、padding 上下 2xl（デスクトップ）または xl（モバイル） | セクション間の余白 |
| CategoryGroup[] | カテゴリごとにグループ化、gap 2xl（デスクトップ）または xl（モバイル） | カテゴリごとに整理 |

### 4.4 カテゴリグループ（CategoryGroup - Organism）

| 要素 | 仕様 | 意図 |
|------|------|------|
| コンテナ | 全幅、padding 上下 2xl（デスクトップ）または xl（モバイル）、背景は交互に`--section-bg` | セクション間の余白と視覚的な区切り |

### 4.5 機能カード（FeatureCard - Organism）

| 要素 | 仕様 | 意図 |

## 5. 情報の見やすさ・UX

| 観点 | 対応 |
|------|------|
| 階層 | H1（ページタイトル）→ H2（カテゴリ）→ H3（機能名）の見出し構造を明確に |
| カテゴリ分け | 機能をカテゴリで分類し、見つけやすくする |
| コントラスト | 本文・背景は AA 以上。作成日・補足情報は`--muted`で十分な比 |
| カード形式 | 各機能をカードで区切り、情報を整理 |
| 1カラムレイアウト | 全幅で縦積み、機能を1つずつ確認しやすい |

---

## 6. レスポンシブ・アクセシビリティ・SEO

| 項目 | 対応 |
|------|------|
| レスポンシブ | ブレークポイントでpadding・font-size・gapを調整。1カラムレイアウト: 全幅で縦積み（すべてのブレークポイント） |
| アクセシビリティ | セマンティックHTML（`<section>`, `<article>`）、適切な見出し構造（h1-h3）、aria-labelledby、キーボード操作対応 |
| パフォーマンス | Suspenseを使用した遅延読み込み（既存の実装を維持）。不要なアニメーションは最小限 |
| SEO | H1に「遊び場」、section＋h2で構造化、適切なメタタグ |

## 7. 拡張性の考慮

### 機能追加の容易さ
- データ構造を配列で管理し、新しい機能を追加する際は配列に追加するだけ
- カテゴリの追加も容易（`Category`型に追加するだけ）
- レイアウトモードの切り替え機能（将来的に追加可能）

### デザインの統一感
- カード形式で統一し、新しい機能を追加しても統一感が保たれる
- カテゴリごとにグループ化することで、機能が増えても整理される

## 10. レイアウトモードの実装

### 1カラムレイアウト（デフォルト）
- すべてのブレークポイントで1カラム（`grid-template-columns: 1fr`）
- カードは全幅で表示
- 機能を1つずつ確認しやすく、拡張性が高い
